# メソッドと impl

型に紐づく関数（メソッド・関連関数）と生成（factory）は `impl` ブロックにまとめます。`impl Type { … }`（無名 impl）はその型固有の振る舞いを、`impl Type as Trait { … }` はトレイト準拠を与えます（[トレイト](08-traits.md)）。

> **無名 impl を書けるのは、その型を自分のモジュールで定義している場合だけ**です（コヒーレンス＝由来の一意性のため）。外部型（他モジュール定義）への実装は、トレイトの所有を問わず名前付き拡張 `#Ext` で行います（→ [拡張](09-extensions.md)、配置の詳細は [モジュール](../04-execution/15-modules.md) の「無名 impl の配置」）。

```plew
pub impl MyType {                          // pub impl → ブロック内のメンバは全て公開
    // インスタンスメソッド（self を読み借用）
    fn instanceMethod(arg: Type) -> ReturnType {
        // メソッド本体
    }

    // 可変メソッド（self を可変借用＝inout self）
    inout fn mutableMethod(arg: Type) {
        // self のフィールドを書き換えられる
    }

    // 消費メソッド（self を move＝呼ぶと self は使えなくなる）
    // ※ コピー可能と分かっているSelfへのmoveはエラー。allowuniqueなSelfは具体化時に適応（→ spec/06）
    move fn intoOther() -> Other {
        // self を消費して別の値を返す
    }

    // 関連関数（静的メソッド相当）
    assoc fn associatedFunction() -> ReturnType {
        // 関連関数本体
    }

    // 関連変数（静的変数相当）
    assoc val associatedValue: Type = defaultValue
}

impl MyType {                              // 修飾なし impl → ブロック内は全て非公開
    fn helper() { /* 定義モジュール内から見える */ }
}
```

- **メンバの可視性は `impl` ブロック単位**（[メンバの可視性](05-structs-enums.md#メンバの可視性)）。`pub impl Type { … }` はブロック内のメソッド・関連関数・`factory` をすべて公開し、修飾なし `impl Type { … }` はすべて非公開（定義モジュール内から見える）にします。**メソッド個別の `pub`（`pub fn`）は書けません** ── 公開と非公開を混在させたいときは `pub impl` と `impl` の **2 ブロックに分けます**（フィールドは読み書きの非対称＝`pub(get)` があるので例外的にフィールド単位 → [メンバの可視性](05-structs-enums.md#メンバの可視性)）。
- **`assoc val` の初期化はトップレベル `val` と同じ規則**：起動時eager・静的な初期化依存順・依存循環はコンパイルエラー・トップレベルawait可（→ [モジュール § トップレベル初期化と実行順序](../04-execution/15-modules.md#トップレベル初期化と実行順序)）。ただし v1 では、型引数を持つ型・trait・impl の stored `assoc val` は reject します。`Box[I32].cache` と `Box[String].cache` が同じ storage を共有するのか、型引数ごとに別 storage を持つのかを構文から直感的に判断しづらいためです。型引数ごとの計算値が必要なら `assoc fn`、明示的な引数を取る factory/関数、または利用側が所有する registry/cache で表します。

- **self のモードは `fn`（読み借用）／`inout fn`（可変借用）／`move fn`（消費）** ── [アクセスモード](../01-basics/03-values.md#アクセスモードborrow--inout--move)と同じ語。`inout fn`/`move fn` は対象が可変束縛／唯一所有のときだけ呼べる。**`Ref` / `FrozenRef` 越しは `fn` のみ、`MutableRef` / `MutexGuard` 越しは `fn`/`inout fn` のみ**（`move fn` は共有を消費するため不可 → [Ref / MutableRef](../01-basics/03-values.md#ref--mutableref--weakref共有参照)）。
- **同期の読み借用receiverの評価**：receiverを先に評価・準備し、明示引数と既定引数を宣言順に評価してから読み借用を開始します。借用はメソッド本体の終了まで続きます。変数・通常のフィールドは格納場所を保持し、呼び出し時点の内容を読みます。関数結果・構築結果・通常の添字取得結果は独立した一時値です。`Ref` / `MutableRef` 越しでは、receiver評価時に選んだセルの同一性と寿命を保持します。後続引数が参照変数を付け替えても、選んだセルは変わりません。親の置換で無効になる内部ポインターを保持してはならず、借用開始時には対象が初期化済みでなければなりません。
- **読み借用中の競合**：receiverへの読み借用と重なる変更・消費・破棄を許可しません。同じ呼び出しの`inout`／`move`引数も対象です。直接所有と共有セル越しの検査の区別は[同時アクセス防止](../01-basics/03-values.md#呼び出し中の同時アクセス防止)に従い、コピー可能なselfだけを無条件snapshotにする例外は設けません。非同期のcopy-self／move-selfはこの同期借用規則と区別します。allowuniqueなSelfの消費モードは[コピー可能な具体化への適応](06-generics.md#所有モードとコピー可能な具体化)に従い、検査済みのgeneric本体を具体化後に再診断しません。
- **発散メソッドの修飾順**：許可形は読み借用の `diverge fn` と、関連関数の `assoc diverge fn` だけである。`inout diverge fn`／`move diverge fn` は、呼び出し元へ戻らない以上 writeback／消費後の accessibility を観測できず意味を持たないため禁止する。`diverge` は戻り型を持たず、`async`／`spawn` とも組み合わせない（→ [関数](../01-basics/04-functions.md#diverge-fn--正常-return-しない関数)）。
- **`async` メソッドは self を借用できない**（`inout self` が境界を跨げない）。非消費なら copy-self（`unique` でない型のみ）、消費なら `async move fn`、await を跨いで self を変更するなら **MutableRef 裏打ち** → [非同期処理とメモリ管理](../04-execution/14-concurrency.md)。

`impl` には `factory`（インスタンス生成）も書けます。生成は型の生成として [構造体と列挙型](05-structs-enums.md) の「インスタンス生成」にまとめています。トレイト準拠の `impl Type as Trait` と `via` は [トレイト](08-traits.md) を参照。

## メソッドのオーバーロード

同じ名前のメソッドを、引数で区別して複数定義できます（オーバーロード）。通常の解決は**ラベルと引数型**で行い、一般のトレイト制約による最特化選択はしません。型引数の単純なコピー能力条件による排他的候補群は、[条件付き呼び出し契約](06-generics.md#能力条件付き候補と重複判定)として扱います。use順による優先順位はありません。

**セレクタ** = 関数・メソッド名 ＋ 順序付き引数ラベル列（`~:`によるラベルなしの位置も含む）。**ラベル列が違えば別の関数・メソッド**であり、同一セレクタ内の型オーバーロードではありません。この規則は通常関数・メソッド・関連関数・factory・trait要求で共通です。

同じ宣言衝突領域で、同一セレクタ内に複数の定義を置く条件：

- **通常は各宣言対の区別位置が必要**：任意の二つの呼び出し形について、対応する引数位置の少なくとも一つで、許された型引数のどの組み合わせでも両方の引数型が同じ型にならないことを、通常の型構造と既に確定した型等式から証明できなければなりません。3候補以上でも比較は各対で行い、全候補に共通する一位置は不要です。型引数の個数や使用位置を揃える必要もありません。同じ型の形でも、単純なコピー能力条件で排他性を証明できる候補群は上記の別契約に従って許します。
- **receiverと各メソッドの型引数を区別**：同じreceiverを持つ候補では、そのreceiverから決まる型引数を共通の型環境として比較します。各メソッド自身が導入する型引数は、別宣言のものとは独立です。名前や型引数リスト内の位置が同じでも同一視しません。receiver由来というだけで常に区別できるわけではなく、`T`と`I64`、`A`と`B`は同じになる可能性があります。
- **構造による証明の範囲**：`Array[I64]`と`Array[Bool]`、`Array[T]`と`Box[U]`は名目型の構造で区別できます。receiverの同じ`T`を共有する`T`と`fn() -> T`も区別できます。同じになるには`T = fn() -> T`という循環した構造的代入が必要ですが、そのような有限の型はなく、有限のoccurs checkで検出できます。一方、独立した型引数`T`と`fn() -> U`は`T = fn() -> I64`、`U = I64`で一致し得ます。再帰的なstruct・enumのフィールドは展開せず、宣言identityを持つ名目型として比較します。
- **確定済み等式と解析限界**：型の別名・参照経路の違いは区別になりません。具体implの`Self`や、既に確定した型等式で正規化できる関連型は、その結果で比較します。未確定の射影を異なる型と仮定したり、一般のwhere制約を探索したりはしません。証明できない場合は保守的に拒否し、重複が証明された場合・未証明の場合・固定の解析上限に達した場合を区別して診断します（[解析上限](06-generics.md#能力条件付き候補と重複判定)）。個々には区別を保証できない複数の引数位置の条件を組み合わせるだけでは受理しません。
- **既定引数の省略形も検査**：[既定引数が追加するセレクタ](../01-basics/04-functions.md#オーバーロードとの関係)にも同じ条件を適用します。完全な引数列で区別できても、区別位置を省略した共通セレクタで条件を満たさなければ宣言エラーです。戻り型・所有モード・型引数の個数だけで型オーバーロードを区別しません。
- **一般のtrait制約は区別に使わない**：`where T: TraitA`の違いだけでオーバーロードを分けられません。能力条件による候補群も、証明可能な範囲を超える重複・優先選択・特殊化は許しません。

```plew
impl A {
    fn f[T](a: I16, b: T) {}
    fn f[T](a: I32, b: T) where T: TraitA {}   // 具体位置 a で区別、b は全員 T
    fn f[T](a: I64, b: T) where T: TraitB {}
    fn f[T, U](b: T, c: U) {}                  // ラベルが (b, c) → 別セレクタ＝別メソッド
}

// 禁止：同セレクタ f(n:) で n が generic vs 具体
// fn f[T](n: T) {}
// fn f(n: I32) {}

// 許可：valueの具体型で区別でき、genericの個数・位置は揃えなくてよい
fn pick[T](value: I64, other: T) {}
fn pick(value: Bool, other: Bool) {}

// 許可：各対を、それぞれa・b・cで区別できる
fn pair[T](a: I64, b: Bool, c: T) {}
fn pair[U](a: Bool, b: U, c: I64) {}
fn pair[V](a: V, b: I64, c: Bool) {}

// 許可：外側の名目型が違い、型引数を推論しなくても区別できる
// Box[T]は通常のgeneric構造体
fn container[T](value: Array[T]) {}
fn container[U](value: Box[U]) {}

// 許可：receiverの同じTを共有する既存API
// impl[T] Optional[T] {
//     fn unwrapOr(fallback: T) -> T
//     fn unwrapOr(fallback: fn() -> T) -> T
// }

// 拒否：各メソッド固有のTとUは独立であり、一致する場合がある
// fn independent[T](value: T) {}
// fn independent[U](value: fn() -> U) {}

// 拒否：省略後のf(value:)には区別位置が残らない
// fn f(kind: I64 = 0I64, value: Bool) {}
// fn f(kind: String = "", value: Bool) {}
```

- すべてのオーバーロードはその型のモジュール内（無名 impl）に集まるので、**衝突検出はモジュール単体のビルドで完結**する（Rust のようなグローバルコヒーレンスは不要）。拡張（`#Ext`）のメソッドはベア解決に参加しないので別扱い。ただし型のベア集合には、型自身のメソッドに加えて**準拠トレイトの公開提供メソッド**（`pub impl Trait` → [トレイト](08-traits.md)）が加わる。同セレクタ・同シグネチャが**同一の出どころ**で重複すれば定義地点でエラー、**別トレイト由来で鉢合わせ**たら併存は許し*曖昧なベア呼び*だけがエラー（`a#P.foo()` で源を選ぶ → [トレイト](08-traits.md#提供メソッドの衝突曖昧はエラー)）。型自身の inherent メソッドとトレイト由来のメソッドが同セレクタで重なる場合、ベアの `a.foo()` は型自身のメソッドを既定として解決し、トレイト由来のものは `a#P.foo()` で選ぶ。
- 解決：ラベルでセレクタを確定し、引数型の構造と許された能力条件を用いて一意な候補を決め、型引数の推論・制約を検査します。allowuniqueなgeneric本体で一候補に決まらない場合は、能力範囲全体の全域性・一意性・共通契約を満たす候補群を保存し、具体化時に保存条件を適用します。再探索や最特化選択は行いません。重複がないと証明できない候補群は保守的に拒否します。
- リテラル引数は文脈（このオーバーロード集合）で型が一意に定まらなければエラー（→ [数値リテラル](../01-basics/02-basic-types.md)）。
- **宣言の受理と呼び出しの一意性は別**：異なる具体型でも、存在型への注入やsendable保証の消去などにより、一つの値が複数候補へ適合することがあります。宣言が有効でも、既存の解決規則で一意に定まらない呼び出しは曖昧エラーです。新しい最特化順位は設けません。引数型等から選択した候補について型引数の個数・推論・制約を検査し、失敗しても別候補へ乗り換えません。
- **拡張違いは別の具体型として区別**：`#Ext` は型の一部なので `f(a: A)` と `f(a: A#P)` は別オーバーロードとして共存できる（[暗黙の拡張キャストは無く](09-extensions.md#拡張ビューの変更は明示暗黙キャストなし) exact 一致で解決・呼び出し側が `#` の有無で選ぶ）。

### メソッド・関連関数は値に取り出せない（クロージャで包む）

`val f = obj.method` や `val f = Type.associatedFunction` のように**メソッド・関連関数をそのまま関数値へ代入することはできません**。これは[名前付き関数宣言](../01-basics/04-functions.md#関数宣言)と同じく「呼び出せる宣言」であって値ではありません。関数値が欲しいときは**明示クロージャで包みます**。

```plew
val f = fn(value: I32) { obj.method(value: value) }   // OK
// val f = obj.method                                  // ✗
val g = fn() -> I32 { return Type.associatedFunction() }  // OK
// val g = Type.associatedFunction                         // ✗
```

理由は 2 つ。**(1) どのオーバーロードか**：メソッドはセレクタ（名前＋ラベル）と引数型でオーバーロードされ得るので `obj.method` 単体では一意でない。クロージャの中の呼び出しが具体型・ラベルでオーバーロードを一意に選ぶ。**(2) `self` のアクセスモード**：メソッドは `self` を `borrow`/`inout`/`move` で取るが、これらを値として持ち回ると borrow は寿命を越えられず inout/move/unique-self は脱出できない。クロージャで包めば、self の取り回しは[クロージャの参照キャプチャ規則](../01-basics/04-functions.md#環境のキャプチャ)が**そのまま**効き、通常の `fn` はsendable保証を持たず、別スレッドへ送るなら [`sendable fn`](../01-basics/04-functions.md#sendable-クロージャ) として明示・検査するので専用規則が要らない。ラベルもクロージャリテラルの引数名として保たれる。[ラベル違いの適応を明示クロージャで行う](../01-basics/04-functions.md#ラベルは型の一部厳密な同一性暗黙変換なし)のと同じ方針（暗黙の魔法を足さない）。セレクタ明示の糖衣（`obj.method(value:)`）は将来の非破壊追加候補。
